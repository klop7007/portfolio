# 통합 ERP 플랫폼 1단계 — 레거시 통합 DB · 조회 API · MCP 서버

> 따로 돌던 레거시 3종을 하나의 통합 ERP 플랫폼으로 전환하는 장기 프로젝트의 **1단계(조회 경로 확보)**.
> 통합 DB 이관·등가검증 → FastAPI 조회 API → MCP 서버까지 세워 운영 서버에 배포했습니다.
> 전체 대비 약 10%. 쓰기 API·회계 통합은 후속 단계이고, 현 단계의 쓰기 착지점은 아직 구 ERP입니다.

| 항목 | 내용 |
|---|---|
| 기간 | 2026.08 ~ 진행 중 (1단계 운영 배포 완료, 외부 AI 연동 개통 전) |
| 역할 | 레거시 분석 · 이관 · API · MCP · 배포 단독 / 프론트 프로토타입은 팀원 산출물 채택 |
| 규모 | 인벤토리 2,322표 판정 · API 8라우터·25엔드포인트 · MCP 도구 14 · 테스트 275 |
| 스택 | FastAPI · PostgreSQL 18 · FastMCP · Vue 3 · Docker Compose |

## 1. 배경 — 사람도 AI도 읽을 수 없는 DB

레거시 3종(VB.NET 상용 ERP · JSP 그룹웨어 · 소스 없는 회계 패키지)이 따로 돌았고, **스키마에 설명이 없어 사람도 AI도 읽을 수 없었습니다.** "AI가 읽을 수 있는 DB"가 최상위 요구였습니다.

- 테이블 2,322 · 프로시저 2,067 · 정의를 볼 수 없는 암호화 개체 58
- 개인 예외 권한 5.7만 건 누적, 그중 99.2%가 전권 → 접근통제 사실상 무력
- 운영·레거시 복원본에 쓰기 금지, 도메인별 쓰기 착지점은 한 곳 유지(병행 공존)
- ITGC·ISO 27001 통제 대조가 완료 판정에 포함, 자격증명·개인정보는 코드·문서·로그·커밋 어디에도 남기지 않음

## 2. 핵심 결정

| 결정 | 선택 | 검토한 대안 | 왜 |
|---|---|---|---|
| AI 접근 방식 | MCP 서버(외부 AI 제품 연동 표준) | 클라이언트마다 함수 호출 도구 직접 구현 | 도구 목록·스키마를 서버가 한 번 소유. 도구가 전부 HTTP 래퍼라 MCP를 걷어내도 API는 남는다 |
| MCP의 위치 | API 앞의 얇은 번역 계층, MCP 코드에 SQL·DB 접속 0 | MCP가 DB를 직접 조회 | 권한 판정·마스킹·감사로그를 API 한 곳에 두면 외부 AI에 조회 도구만 열어도 통제가 깨지지 않는다 |
| DB 엔진 | PostgreSQL 18로 전환 완주 | SQL Server 유지(초기 설계) | 라이선스·개방성. 12표 전수 지문 대조로 등가 증명 후 전환. 대가로 생긴 운영 부담은 일 백업·주 basebackup·WAL PITR을 배포 조건에, 복원 리허설을 개통 조건에 넣어 상쇄 |
| 테이블 판정 | 4축 근거(운영 접근 이력·데이터 최신일·프로시저 쓰기·화면 참조) | 이름 패턴(bak·temp·날짜) 단독 판정 | 3축 근거 없이는 제외하지 않는다. **판정 불가는 "보류"지 "폐기"가 아니다** — 불변식으로 명문화 |
| 전환 방식 | 도메인별 순차 이관, 쓰기 착지점은 항상 한 곳 | 빅뱅 컷오버 | 20년 레거시를 멈추지 않고 옮긴다. 조회부터 새 경로로 돌리고 착지점은 도메인마다 스위치 |
| AI 통제 | 훅이 허용 서버 AND 허용 DB 이중 화이트리스트 밖 쓰기를 차단 + 불변식 11개 | 에이전트 지침으로 유도 | 원격 실행·OPENQUERY·표준입력 공급 같은 우회 경로 3종을 실제로 찾아 막았고, 훅 자체를 테스트 30건으로 고정 |

## 3. 구현

```
VB.NET 상용 ERP (2,322표) ─┐
JSP 그룹웨어 ──────────────┼─▶ 전수 인벤토리 · 4축 판정 · 도메인별 이관 · 등가검증
회계 패키지 ───────────────┘                    │
                                                ▼
                            통합 DB · PostgreSQL 18 (한글 COMMENT · 호환 뷰)
                                                │
                                                ▼
                     FastAPI 조회 API — JWT · 법인 스코프 · 감사로그 2종 · 속도제한
                                    │                          │
                                    ▼                          ▼
                     Vue 3 관리 화면 (7화면 · 조직도 SVG)   MCP 서버 · 도구 14종
                                                          (TLS · Bearer JWT · 429)
                                                                   │
                                                                   ▼
                                                              외부 AI 채팅
```

- **인벤토리·판정** 2,322표를 4축 근거로 활성 547 / 조회전용 270 / 보류 491 / 폐기후보 985. 표마다 근거 기록
- **이관·등가검증** 검증 컬럼을 카탈로그에서 자동 도출해 "침묵 PASS" 제거. 행수 + 전 컬럼 해시 다중집합 대조
- **법인 스코프** 모든 조회 라우터에 활성 법인 단독 스코프 강제. 법인 없는 비관리자는 403(fail-closed)
- **세션·감사** 5회 실패 잠금, TTL 240분·절대 상한 12시간. 인증 이벤트·조회 호출을 append-only 로그 2종에 기록, 로그인·비밀번호 본문은 하드 제외. DB 롤에 쓰기 권한 없음(UPDATE·DELETE 거부 실측)
- **MCP 서버** 도구 14종 전부 API HTTP 래퍼. TLS·허용 호스트 미설정 시 비로컬 기동 거부, 속도제한 300/분, 민감 인사정보는 어떤 도구로도 비노출
- **신원 모델** 겸직·복수 사번은 메인 사번 로그인 + 링크 사번 전환. 합집합을 주지 않는 이유는 행위마다 어느 신원으로 했는지 감사로그에 남아야 하고, 합집합은 최소권한을 무력화하기 때문. 매핑 84건 확정, 불일치 97건 보류
- **배포** 운영 리눅스 서버 Docker Compose 3컨테이너, 일 백업 + 주 basebackup + WAL PITR

## 4. 결과 (1단계 기준)

| 지표 | 전 | 후 · 측정 근거 |

| 운영 배포 | 없음 | 착수 12일 만에 운영 서버 Docker Compose 3컨테이너. 기동·헬스 5항목 통과, 마스터 11표 행수 로컬과 일치 |

**남은 단계**: 쓰기 API → 도메인별 쓰기 착지점 전환 → 회계 통합 → 외부 AI 개통. 1단계 산출물(문서·테스트 275건·이관 절차)은 인수인계 가능한 상태로 정리.

## 5. 회고

- **잘한 것**: 판정 불가를 "보류" 버킷으로 남기고, 등가검증 없이는 완료를 선언하지 않는 규칙을 먼저 세웠다
- **다시 한다면**: 엔진 전환을 처음부터 결정한다. 오류 메시지 파싱 → sqlstate, LIKE → ILIKE, 대소문자 컬럼명이 프론트 타입까지 파급됐다
- **배운 것**: DB 이식성은 SQL 문법이 아니라 부수 계약에서 깨진다. 다중집합 등가검증은 로케일 정렬 차이를 잡지 못한다. 시험 단계에서 AI 클라이언트 호출이 3분에 423회 폭주해 속도제한·목록 상한 50으로 막았고, 잠금 중 재시도가 잠금을 무한 연장하던 결함도 이때 드러나 고쳤다
