# 그룹웨어–ERP 근태 연동 DX

> 그룹웨어(전자결재)와 ERP(인사·근태)가 서로 데이터를 넘기지 못해 사람이 대조하던 근태 업무를,
> **그룹웨어 신청 데이터 구조화 → ERP 일 근태 배치 연동**으로 자동화했습니다.
> 두 시스템에 걸쳐 화면·SQL 매퍼·스토어드 프로시저·배치 잡·데이터 이관까지 1인 설계·반영.

| 항목 | 내용 |
|---|---|
| 기간 | 2026.08 ~ 09 (설계 → 반영 → 정책 개정 3회 → 운영 안정화) |
| 역할 | 1인 — 실측 · 설계 · 구현 · 데이터 이관 · 배치 이관 · 현업 협의 · 문서화 |
| 그룹웨어 | JSP Model 1 + iBATIS 2, Tomcat 7 — 화면 1 · 매퍼 쿼리 4 · 테이블 1 · 이관 570건 |
| ERP | MS SQL Server 2014, T-SQL SP + SQL Agent — 신규 SP 3 · 패치 1 · 테이블 2 · 배치 잡 1 |

---

## 1. 배경 — 두 시스템 사이에 사람이 있었다

유연근무 신청은 **그룹웨어** 전자결재로, 출퇴근 기록과 근태 판정은 **ERP**에서 이뤄집니다. 그런데 신청서가 에디터 HTML 표로 저장돼 있어 **ERP로 넘길 구조화된 데이터가 없었고**, ERP에는 **지각 계산 로직 자체가 없었습니다.** 그 사이를 담당자가 눈과 엑셀로 메우고 있었습니다.

- 그룹웨어: 신청 현황을 쿼리로 볼 수 없어 담당자가 문서를 하나씩 열어 확인
- 기간 중복 신청을 막을 근거 없음
- 저장·삭제 로직에 양식 분기 없음 → 결재 마스터만 남음
- ERP: 일 근태 4개월치 2만여 행 실측 → 지각 시간 채워진 행 **0건** (컬럼만 있고 로직 없음)

요구: "신청자는 본인 유형, 나머지는 표준 출근시각 기준으로 ERP에서 지각 자동 판정" → 먼저 그룹웨어 쪽 신청 데이터 구조화가 필요

## 2. 설계 원칙

**하위호환을 깨지 않는다.** 전환 전 문서 570건은 화면·인쇄가 전과 동일해야 하고, 결재 진행 중 문서가 오류 나면 안 된다.

**기존 결재 인터페이스를 건드리지 않는다.** 다른 근태 양식은 최종결재 시 근태 이벤트 테이블에 행을 쓰는 공통 경로를 탄다. 유연근무는 "그 날의 이벤트"가 아니라 "기간의 기준값"이라 성격이 다르고, 그 경로에 넣으면 다른 처리 로직과 경합해 실제 근태를 가린다. 대신 결재 마스터의 승인 상태를 읽어 **반려·삭제·상신취소 시 원복이 자동으로 따라오게** 했다.

**정책 값은 DB에 남긴다.** 유형별 시각 정의는 한 곳에 두되, 저장 시 선택된 시각을 그대로 기록 → 유형표가 바뀌어도 과거 문서 표시와 지각 판정은 불변.

## 3. 구현

```
[그룹웨어]  유연근무 신청서 ──▶ 구조화 상세 테이블 ──┐
                                                  │ 결재 승인분만
[ERP]       카드리더·출장·근태신청 ──▶ 일 근태 ──┼──▶ 지각 계산 SP ──▶ 지각시간·근태코드
            사업장 근무시간 기준 ─────────────────┘         (SQL Agent, 매일 새벽)
```

### 3-1. 그룹웨어 — 양식 구조화 (DX 전환)

```
전환 전   에디터 HTML 표  ──▶  결재 본문 (문자열)

전환 후   폼 컨트롤(라디오·datepicker·textarea)
            ├─▶ 전용 상세 테이블 (유형·출퇴근시각·적용기간·사유)
            └─▶ 결재 본문 스냅샷 (인쇄·열람용)
```

- 한 JSP가 신규작성·상세·상신수정·복사를 겸함 → 문서번호 유무 + 상세 행 유무로 **구조화 폼 / 레거시 렌더** 분기. 상세 조회 실패 시 레거시 경로로 폴백해 기존 문서는 항상 열림
- 구조화 필드가 비면 상세 INSERT 생략 → 구 문서 상신수정 시 빈 행 방지
- 목록에 신청유형·적용기간 컬럼 추가, 결재완료 문서와 기간 겹침 확인 AJAX 신설
- 인증 체크 누락 화면에 인증 체크 추가
- 신규 쿼리 전부 파라미터 바인딩 — 레거시의 문자열 치환 패턴을 신규 코드에 쓰지 않는 규칙 문서화

### 3-2. 그룹웨어 — 레거시 문서 570건 이관

본문 HTML 표를 파싱해 구조화 테이블로 옮기는 Python 스크립트 작성.

| 구분 | 건수 |
|---|---|
| 자동 파싱 | 534 |
| 수기 보정 (현업 엑셀 값을 파서가 병합) | 33 |
| 제외 확정 (테스트·미상신·유형 미선택) | 3 |
| **이관 완료** | **567 / 570 (99.5%)** |

- **유형은 문자가 아니라 시각으로 매핑** — 구형 3종·현행 5종이라 같은 이름이 다른 시각을 가리킴
- 트랜잭션 + 존재 확인 가드로 재실행 안전, 이관 ID로 일괄 원복 가능
- 검증: 시각·날짜 형식 오류 0건, 사번 누락 0건, 유형↔시각 정합 100%

### 3-3. ERP — 일 근태 지각 계산 신설 (T-SQL)

```
[현행]  카드리더 + 외부 원시근태(링크서버) + 근태신청 + 출장(링크서버)
          → 일근태 생성 SP → 일 근태 테이블           ※ 지각 미설정

[신설]  일 근태 + 유연근무 상세(승인분) + 근무시간 기준
          → 지각 계산 SP → 일 근태.지각시간 + 근태코드

[배치]  사업장 루프 래퍼 SP → SQL Agent Job 매일 새벽
```

기준 출근시각 우선순위:
1. 유연근무 신청 (개인·기간별, 결재완료분만). 같은 기간에 여러 문서면 **시작일이 늦은 문서 우선** — 기간 중간 변경을 재신청으로 처리하는 근거
2. 사업장별 근무시간 기준 테이블
3. 둘 다 없으면 표준 출근시각 — 실측상
