# 레거시 그룹웨어 전자결재 DX — 신청서 구조화와 근태 자동 판정 연동

> 15년 된 JSP 그룹웨어의 전자결재 양식을 "에디터 안의 HTML 표"에서 "구조화 데이터"로 바꾸고,
> 그 데이터를 ERP 일 근태 배치에 연결해 **존재하지 않던 지각 자동 판정을 신설**했습니다.
> 화면·SQL 매퍼·스토어드 프로시저·배치 잡·데이터 이관까지 1인 설계·반영.

| 항목 | 내용 |
|---|---|
| 기간 | 2026.08 ~ 2026.09 (설계 → 반영 → 정책 개정 3회 → 운영 안정화) |
| 역할 | 1인 — 현황 실측 · 설계 · JSP/iBATIS/T-SQL 구현 · 데이터 이관 · 배치 이관 · 현업(인사) 정책 협의 · 문서화 |
| 대상 시스템 | 사내 그룹웨어 (JSP Model 1 + iBATIS 2 + MS SQL Server 2014, Tomcat 7) — 전자결재 양식 수백 개, 매퍼 2만 줄 이상 |
| 규모 | 신규 SP 3 · 기존 SP 패치 1 · 신규 테이블 3 · 매퍼 쿼리 4 · 배치 잡 1 · 레거시 문서 이관 570건 |

---

## 1. 배경 — 데이터가 "그림"으로만 있었다

유연근무제 신청서가 에디터 HTML 표로 저장돼 있어 **구조화된 데이터가 없었고**, ERP에는 **지각 계산 로직 자체가 없었습니다.**

- 신청 현황을 쿼리로 볼 수 없어 담당자가 문서를 하나씩 열어 확인
- 기간 중복 신청을 막을 근거 없음
- 저장·삭제 로직에 양식 분기 없음 → 결재 마스터만 남음
- 일 근태 4개월치 2만여 행 실측 → 지각 시간 채워진 행 **0건** (컬럼만 있고 로직 없음)

요구: "신청자는 본인 유형, 나머지는 표준 출근시각 기준으로 지각 자동 판정" → 먼저 신청 데이터 구조화가 필요

## 2. 설계 원칙

**하위호환을 깨지 않는다.** 전환 전 문서 570건은 화면·인쇄가 전과 동일해야 하고, 결재 진행 중 문서가 오류 나면 안 된다.

**기존 결재 인터페이스를 건드리지 않는다.** 다른 근태 양식은 최종결재 시 근태 이벤트 테이블에 행을 쓰는 공통 경로를 탄다. 유연근무는 "그 날의 이벤트"가 아니라 "기간의 기준값"이라 성격이 다르고, 그 경로에 넣으면 다른 처리 로직과 경합해 실제 근태를 가린다. 대신 결재 마스터의 승인 상태를 읽어 **반려·삭제·상신취소 시 원복이 자동으로 따라오게** 했다.

**정책 값은 DB에 남긴다.** 유형별 시각 정의는 한 곳에 두되, 저장 시 선택된 시각을 그대로 기록 → 유형표가 바뀌어도 과거 문서 표시와 지각 판정은 불변.

## 3. 구현

### 3-1. 양식 구조화 (DX 전환)

```
전환 전   에디터 HTML 표  ──▶  결재 본문 (문자열)

전환 후   폼 컨트롤(라디오·datepicker·textarea)
            ├─▶ 전용 상세 테이블 (유형·출퇴근시각·적용기간·사유)
            └─▶ 결재 본문 스냅샷 (인쇄·열람용)
```

- 한 JSP가 신규작성·상세·상신수정·복사를 겸함 → 문서번호 유무 + 상세 행 유무로 **구조화 폼 / 레거시 렌더** 분기. 상세 조회 실패 시 레거시 경로로 폴백해 기존 문서는 항상 열림
- 구조화 필드가 비면 상세 INSERT 생략 → 구 문서 상신수정 시 빈 행 방지
- 목록에 신청유형·적용기간 컬럼 추가, 결재완료 문서와 기간 겹침 확인 AJAX 신설
- 인증 체크 누락 화면에 인증 체크 추가
- 신규 쿼리 전부 파라미터 바인딩 — 레거시의 문자열 치환 패턴을 신규 코드에 쓰지 않는 규칙 문서화

### 3-2. 레거시 문서 570건 이관

본문 HTML 표를 파싱해 구조화 테이블로 옮기는 Python 스크립트 작성.

| 구분 | 건수 |
|---|---|
| 자동 파싱 | 534 |
| 수기 보정 (현업 엑셀 값을 파서가 병합) | 33 |
| 제외 확정 (테스트·미상신·유형 미선택) | 3 |
| **이관 완료** | **567 / 570 (99.5%)** |

- **유형은 문자가 아니라 시각으로 매핑** — 구형 3종·현행 5종이라 같은 이름이 다른 시각을 가리킴
- 트랜잭션 + 존재 확인 가드로 재실행 안전, 이관 ID로 일괄 원복 가능
- 검증: 시각·날짜 형식 오류 0건, 사번 누락 0건, 유형↔시각 정합 100%

### 3-3. 일 근태 지각 계산 신설 (T-SQL)

```
[현행]  카드리더 + 외부 원시근태(링크서버) + 근태신청 + 출장(링크서버)
          → 일근태 생성 SP → 일 근태 테이블           ※ 지각 미설정

[신설]  일 근태 + 유연근무 상세(승인분) + 근무시간 기준
          → 지각 계산 SP → 일 근태.지각시간 + 근태코드

[배치]  사업장 루프 래퍼 SP → SQL Agent Job 매일 새벽
```

기준 출근시각 우선순위:
1. 유연근무 신청 (개인·기간별, 결재완료분만). 같은 기간에 여러 문서면 **시작일이 늦은 문서 우선** — 기간 중간 변경을 재신청으로 처리하는 근거
2. 사업장별 근무시간 기준 테이블
3. 둘 다 없으면 표준 출근시각 — 실측상 대부분 사업장이 기준 미등록이라 **이 경로가 실제 주경로**

설계 중 확인한 함정과 대응:
- **ERP "일근태 생성" 버튼이 지각을 지운다.** 기존 SP가 해당 기간 행을 삭제 후 재생성하기 때문 → 기존 SP 끝에서 신규 SP를 호출하도록 패치
- **링크서버 장애 시 배치 전체가 죽는다.** 링크서버 조회 두 곳을 TRY/CATCH로 감싸 해당 소스만 제외하고 진행
- 근태코드 있는 날·야간조 제외, 개인 예외자 테이블, 시운전 모드(UPDATE 없이 대상만 조회)
- **급여 무영향 검증** — 지각 코드가 급여 계산에 매핑되지 않음을 확인한 뒤 코드 세팅 결정

### 3-4. 신청 정책 개정 3회

처음엔 화면·매퍼·DB CHECK 제약 3층으로 신청 기간을 차단 → 운영 요구로 "저장은 항상 허용, 상신 시에만 조건부 검증"으로 완화.

- 검증 위치를 저장(입력 완결성)과 상신(정책)으로 분리
- 3층 차단 제거, 정책을 화면 한 곳에 모아 변경 비용 축소
- 시스템 전환 유예용 한시 해제 옵션 (기한 도래 시 자동 원복)

## 4. 운영 반영

- **개발 VM → 운영 이관 절차서**: 객체 6개 + 잡 1개 의존 순서, DB명 치환 위치, 기존 SP 덮어쓰기 전 diff 필수 등 함정 4개 명시
- 사전조건 쿼리(급여 매핑 확인 등) 중 하나라도 어긋나면 중단하는 게이트
- 이관 후 검증 세트: 객체 존재 → 패치 삽입 → 시운전 → 정합성(지각시간·근태코드 불일치 0건)
- 배치 실행 로그 테이블로 일별 추적, 휴가 반영 점검 스크립트

## 5. 함께 정리한 것

- 소스 관리 체계 정비 — 날짜 접미사 백업본 정리, 웹루트에서 URL로 실행되던 백업 파일 목록화
- 전자결재 화면별 카탈로그(양식·상태 코드·테이블·SP 사전) + 화면별 SQL 사본 규약 — SP에 숨은 쿼리를 못 찾던 문제 해소
- 설정·매퍼 경로 불일치로 나던 전 페이지 장애 패턴 문서화
- Claude Code 에이전트·훅 구성 — 설정 파일 열람 차단, 위험 셸 명령 가드, DB 조회 보고 시 실행 SQL 동반

## 6. 성과

- 신청 현황 확인: 문서 개별 열람 → 쿼리 1회
- 지각 판정: 수작업 없음 → 매일 자동, 사업장별 일괄
- 레거시 이관 정확도 99.5% (567/570), 형식 오류 0건
- 정책 3회 변경에도 배치·DB 무수정 — 변경 지점이 화면 한 곳으로 수렴

## 7. 회고

- **잘한 것**: 코드보다 실측이 먼저. "지각 계산이 안 된다"는 요구를 "원래 없었다"로 바로잡았고, 기준 테이블이 대부분 사업장에 없다는 걸 알았기에 기본값 경로를 주경로로 설계
- **잘한 것**: 기존 인터페이스를 우회한 이유를 문서에 남김 — 다음 사람이 "왜 공통 경로를 안 탔지?" 하고 되돌리지 않도록
- **아쉬운 것**: 적용기간 규칙이 화면 JS에만 있음 → 직접 POST 시 규칙 밖 값 저장 가능, 서버 검증 필요
- **아쉬운 것**: 목록이 행마다 상세를 조회(N+1). 공통 목록 쿼리를 안 건드리려 택한 타협, 전용 목록 쿼리로 교체 필요
