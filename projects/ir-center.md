## 1. 배경 — 주주와 회사 사이에 창구가 없었다

IR 정보는 홈페이지 공시 페이지에 흩어져 있고, **주주가 질문하고 회사가 답변을 관리할 곳이 없었습니다.** 실명 확인된 사용자만 글을 쓰되 개인정보는 최소한만 보관해야 했고, 인프라 제약도 있었습니다.

- 게시판은 **실명 확인된 사용자만** 작성 가능, 개인정보(이름·전화·CI)는 최소 보관
- 운영 DB가 **MS SQL Server 2014** 고정 → 최신 SQL 구문 사용 불가
- 신규 서버 없이 **기존 공용 웹서버에 합류**, 다른 서비스 무중단 유지

## 2. 아키텍처

```
Browser ──► Apache :443 (TLS) ──► Next.js :3001
              nginx :80 → 443        │
                                     ├─ Server Component (SSR, force-dynamic)
                                     ├─ Server Action / Route Handler ─┐
                                     └─ Client Component (폼 상태만)   │
                                                                       ▼
                                          데이터 접근 계층 (server-only) ──► MSSQL 2014
                                          세션 모듈      httpOnly JWT
                                          본인인증 모듈  PortOne API
                                          메일 모듈      SMTP
```

**3-tier 데이터 흐름을 규칙으로 강제**했습니다.

1. **데이터 접근 계층** — `server-only`로 클라이언트 import 차단, 모든 쿼리 파라미터 바인딩(문자열 보간 금지)
2. **Server Action / Route Handler** — 클라이언트 인자를 믿지 않고 서버에서 세션 재검증 후 DAL 호출, `revalidatePath`로 캐시 무효화
3. **Client Component** — 폼 상태만 관리, 결과는 Server Action 반환값으로 처리

## 3. 핵심 구현

### 3-1. 본인인증 회원가입 — 검증 결과를 클라이언트가 조작할 수 없게

- 브라우저 SDK 인증 → 서버가 PortOne API로 `VERIFIED` 상태 직접 재확인
- 검증된 이름·전화·CI를 **서버 발급 브릿지 토큰(httpOnly, TTL 10분)** 에 봉인
- 회원가입 API는 브릿지 토큰만 신뢰 → 클라이언트가 보낸 개인정보 필드는 무시
- 본인 식별자는 CI → 같은 CI 재가입은 인증 수단과 무관하게 차단, 운영 환경에서 CI 없는 가입 거부
- 카카오·네이버 OAuth 직접 연동 + KG이니시스를 거쳐 PortOne으로 통합 → 연동처 3곳 → 1곳

### 3-2. 세션 즉시 무효화 — JWT의 한계 보완

- httpOnly 쿠키 + jose JWT(HS256), 페이로드 구분 값으로 관리자·회원 세션 분리
- **DB 세션 버전 카운터**로 발급 후 취소 불가 문제 해결 → 회원 정지·비밀번호 변경 시 카운터 +1, 기존 토큰 즉시 무효
- 고위험 액션(글 삭제·관리자 답변·게시판 설정·회원 상태 변경)에만 카운터 검증 → 일반 조회 성능 유지
- 구버전 토큰은 graceful 통과 → 배포 시 강제 로그아웃 없이 전환

### 3-3. 비밀글 권한 모델 — 우회 경로 차단

- 목록·상세 **양쪽에서 동일한 권한 판정 함수**(게시판·글·열람자 → 공개 범위) 사용
- 권한 부족 시 DAL이 본문·답변을 **서버에서 NULL로 마스킹** → 원문이 클라이언트에 내려가지 않음
- 작성자명 중간 마스킹(김민우 → 김*우), 관리자/IR 답변은 실명
- 원글/답변 depth 스레드, soft delete

### 3-4. 레거시 DB(MSSQL 2014) 대응

- 2016+ 전용 구문(`STRING_AGG`, `DROP IF EXISTS`, `JSON_VALUE`, `CREATE OR ALTER`, `TRIM`) 금지 규칙 문서화 → 코드 리뷰 기준
- Node 18/OpenSSL 3가 SQL Server 2014의 SHA-1 인증서 거부 → TLS `SECLEVEL=0`으로 연결 복구
- Next.js가 `mssql`/`tedious` 번들링 시 타입 prototype 파손 → `serverComponentsExternalPackages` 등록
- 커넥션 풀을 `globalThis`에 캐시 → dev 핫리로드 풀 누수 방지, 실패한 풀은 캐시하지 않고 리셋
- `GO` 배치 분할 + pre/post-check 마이그레이션 러너 자작 → 8건 운영 적용

### 3-5. 보안 자체 점검 — 출시 전 CWE 기준 점검·수정

| HIGH | CWE-489 테스트용 폴백 식별자 운영 잔존 | 운영 환경에서 폴백 경로 제거 |

## 4. 운영과 배포

- 기존 공용 웹서버에 vhost 합류 — Apache 443 TLS 종단 + nginx 80 리다이렉트, 와일드카드 인증서 재사용
- PM2 / systemd 상주 방식 2종 준비, 배포 가이드·DNS 요청서·env 템플릿 문서화
- **운영 진단 스크립트 27종**(DB 점검·로그인 검증·시드·마이그레이션) read-only 원칙으로 작성 → 장애 시 즉시 상태 확인
- 개인정보처리방침 개정(접속기록 보관·유출 통지 기한·CI 수집 항목) 반영

## 5. 개발 프로세스

- Conventional Commits(`feat/fix/style/chore/docs`) 99건, 작업 브랜치 → 메인 병합
- 아키텍처·금지 구문·보안 규칙을 프로젝트 문서로 정리, Claude Code 에이전트/훅 구성 — DB 접속 정보 자동 주입, 위험 명령 차단, 편집 후 규칙 리마인더

## 6. 성과

- 1인 풀스택으로 11주 만에 개발·배포, 기존 웹서버 합류로 인프라 추가 비용 0원
- 카카오·네이버·PASS·토스 4종 인증을 PortOne 1채널로 통합 → 연동·유지보수 대상 3곳 → 1곳
- 서버 측 검증(브릿지 토큰·세션 즉시 폐기·비밀글 마스킹)으로 출시 후 2개월간 인증 관련 장애 0건

## 7. 회고

- **잘한 것**: 클라이언트 입력을 신뢰하지 않는 원칙을 처음부터 구조(브릿지 토큰·서버 세션 재검증·DAL server-only)로 강제 → 이후 보안 점검에서 구조적 문제 없음
- **아쉬운 것**: 자동화 테스트 없이 진단 스크립트로만 검증 → 다음엔 인증 흐름만이라도 통합 테스트 선작성
- **남은 리스크**: 인메모리 rate-limit은 단일 프로세스 전제 → 클러스터 확장 시 Redis로 교체 필요
